# Исправление 500 ошибки в админке ContactSocialLink

## Проблема

В админке Django при сохранении `ContactSocialLink` (изменение порядка или добавление новой записи) возникает Server Error (500).

### Корневая причина ошибки при смене порядка (список)

В `contacts/admin.py:88-89` модель `ContactSocialLinkAdmin` использует `list_editable = ('order', 'is_active')`, что позволяет редактировать порядок прямо в списке. При попытке поменять порядок местами (например, Instagram 1→2, Facebook 2→1) Django сохраняет записи последовательно. Когда Instagram сохраняется с `order=2`, запись Facebook всё ещё имеет `order=2` — срабатывает `UniqueConstraint` (`unique_site_config_social_order` в `contacts/models.py:192-195`), что приводит к необработанной ошибке и 500.

### Корневая причина ошибки при добавлении

`ContactSocialLinkAdmin` имеет `exclude = ('site_config',)` (строка 87). Поле `site_config` исключено из формы, и Django не вызывает `get_default_site_config()` как default для FK при сохранении через админку. Если `SiteConfig` не привязывается корректно — возникает ошибка сохранения.

Также `ContactSocialLinkFormSet.clean()` (строки 73-80) поднимает `ValidationError` из `__all__` ошибок форм, но Django admin changelist может не обрабатывать эту ошибку корректно, превращая её в 500.

## План исправлений

### 1. Исправить смену порядка в списке — `contacts/admin.py`

**Файл:** `backend/contacts/admin.py`

Добавить `save_formset()` в `ContactSocialLinkAdmin`, который при смене `order` выполняет перестановку в транзакции сначала освобождая конфликтующие значения:

```python
@admin.register(ContactSocialLink)
class ContactSocialLinkAdmin(BaseAdmin):
    # ... существующий код ...

    def save_model(self, request, obj, form, change):
        if change and 'order' in form.changed_data:
            new_order = obj.order
            old_order = form.initial.get('order')
            if old_order is not None and new_order != old_order:
                # Освобождаем целевой order, если он занят другой записью
                conflict = ContactSocialLink.objects.filter(
                    site_config=obj.site_config,
                    order=new_order,
                ).exclude(pk=obj.pk).first()
                if conflict:
                    conflict.order = old_order
                    conflict.save(update_fields=['order'])
        if not obj.site_config_id:
            obj.site_config = get_default_site_config()
        super().save_model(request, obj, form, change)
```

### 2. Ограничить диапазон `order` — `contacts/models.py`

**Файлы:**
- `backend/contacts/models.py` — поле `order`
- `backend/contacts/constants.py` — добавить константы

Изменить `order` с `PositiveSmallIntegerField` на `PositiveSmallIntegerField` с `validators=[MinValueValidator(1), MaxValueValidator(6)]`:

```python
# constants.py
SOCIAL_ORDER_MIN_VALUE = 1
SOCIAL_ORDER_MAX_VALUE = 6  # п. 1.8 — до 6 иконок
```

```python
# models.py — поле order
from django.core.validators import MinValueValidator, MaxValueValidator

order = models.PositiveSmallIntegerField(
    default=constants.SOCIAL_ORDER_MIN_VALUE,
    validators=[
        MinValueValidator(constants.SOCIAL_ORDER_MIN_VALUE),
        MaxValueValidator(constants.SOCIAL_ORDER_MAX_VALUE),
    ],
    verbose_name=_('Порядок отображения'),
)
```

### 3. Сгенерировать миграцию

```bash
python manage.py makemigrations contacts
```

Изменение `validators` не затрагивает БД-тип колонки, миграция будет только для Python-уровня (без SQL).
